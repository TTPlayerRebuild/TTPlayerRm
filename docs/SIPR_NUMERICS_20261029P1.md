# SIPR 低码率初始化与数值路径恢复（2026.10.29p1）

## 本轮结论

本轮继续验证 [前轮 SIPR 恢复记录](SIPR_PARITY_20261029.md) 中的低码率残差。已确认 5 kbps 的 57 LSB 局部误差主要不是整数量化问题，而是现代即时解码省去原版首个静音流水线帧时，没有保留该帧产生的 ISP 初始历史。

现在直接初始化为原版预热之后的 ISP，不制造静音帧、不延迟输出、不丢弃有效尾部。此外恢复原始 Hz 码本、预测常量、float ISP→LPC 路径，以及与上游表不同的原版激励插值系数。五个样本、四种码率的最终输出均降至最多 1 LSB 的差异。5k 的 RMS 从 0.607580 降为 0.050909 LSB；6.5k 从 0.550174 降为 0.048113；8.5k 从 0.459214 降为 0.066064。16k 保持前轮结果，不变更算法。

这不是所有模式逐位一致。下文分别列出已恢复的函数、测量结果及尚存的数值边界。前轮文档中“低码率未修改”“5k 峰值 57”是前轮产物的历史状态，本轮对应部分由本文更新。

## 已恢复的通用实现

### 1. 频率码本与解量化

原 DLL 的均值位于 `614bbb34`，五组二维码本依次位于 `614bbb60`、`614bbd60`、`614bc160`、`614bc560`、`614bc960`，索引位宽为 6、7、7、7、5。原数据是 binary32 Hz 值；将其预先归一化为弧度、再以六位小数保存，会产生额外精度损失。

新实现直接保存原始 float Hz，按原顺序计算：

`float(double(previous_quantizer) * 0.33f + mean_hz + current_quantizer)`

`0.33f` 的实际值为 `0.33000001311302185`，不能替换成 double `0.33`。每项只在原版写回状态的位置收窄到 float。

约束函数 `614b02d0/614b0470` 对前九项先进行一次相邻交换，再逐项施加 50 Hz 最小间隔。这里没有改成完整排序。最后一项限制到 [-325, 520] Hz，前九项取 `cos(hz * 0.0007853981635)`，最后一项乘 binary32 的 `1/650`。完整样本与独立索引测试均覆盖这条路径。

### 2. ISP 插值与 LPC

原 `614aae10` 把 `1 / subframe_count` 以及初始 `0.5 / subframe_count` 分别存成 float；子帧权重每次通过 float 加法推进。前一帧与当前帧 ISP 的乘加使用较宽的中间值，插值结果写回 float。

`614b0490` 使用 float 多项式历史，最后一项 ISP 直接成为最后一个 LPC 系数。新实现保留这些中间存储点，不把全部多项式状态改为 double，也不使用普通十阶 LSP 转换代替 ISP 转换。

### 3. 5k 的初始 ISP

原普通低码率初始 ISP 是四位小数的十项常量，首项 `0.9595f`，末项 `-0.9595f`。直接计算等间隔角度的余弦并不完全相同。

5k 另有关键差异：原 `614a3340` 第一轮使用已标记为错误的上一帧参数，产生 240 个零样本。这一轮把 ISP 历史更新为均值频率转换得到的 ISP；随后才用这组历史解码真实第一帧。初始均值状态的最后一项变为约 `0.1483940035`，与原始网格的 `-0.9595f` 差异很大。

直接运行原函数，比较预热前后的状态，并与新初始化逐项比较，确认：

- 普通低码率初始十项与原版逐位相同。
- 5k 原版实际预热后的十项，与新实现直接初始化的十项逐位相同。
- 这次静音预热不产生有效激励、合成或增益历史；与真实音频有关的持久状态差异是 ISP。

因此只恢复初始状态，继续即时输出真实第一帧。两个完整样本仍分别返回 161,280 / 115,200 个样本。前轮验证的非静音待输出尾部仍须保留；不能为了重现旧宿主的时间偏移而删去尾音。

`sipr.rm` 的真实首帧 240 个样本，修复前峰值误差 57、RMS 11.071924 LSB，修复后峰值 1、RMS 0.111803 LSB。两份 5k 文件各在第 32、100、200 包结束处重新验证，六段待输出尾部的峰值为 241～11,415 LSB，全部保留；原 DLL 后继包使用重复包或零包时，这 240 个待输出样本逐字节相同。

### 4. 自适应激励插值

仅恢复以上谱参数后，6.5/8.5/5k 仍分别存在 7/4/3 LSB 峰值残差。沿首次激励状态差异继续回溯，发现原 `614aade0` 使用 `614b74d0` 的 40 个 float 系数，与上游通用 `ff_b60_sinc` 的相应相位并不相同。例如原中心系数为 `0.8985170125961304f`，上游为约 `0.898529`；原相邻系数为 `0.7692710161209106f`，上游约 `0.769257`。这不是同一个数值换一种书写形式。

原 `614aa6f0` 按整数延迟和三个分数相位，从过去 20 个连续样本构造激励，系数以正向或反向步长 2 遍历，在 x87 中从左到右累计后存为 float。短延迟时输入和输出会重叠，必须按样本顺序更新。

新 `tt_sipr_low_interpolate` 只替代低码率 SIPR 的这一次调用，使用原 40 项表和相同累计顺序；没有修改共享的 `ff_b60_sinc` 或 `ff_acelp_interpolatef`，也不会影响其他 codec。加入这一项后，四个低码率样本全部降至最多 1 LSB。高通／增益候选没有参与这一改善。

## 剩余边界及未采用的候选

谱参数及激励插值已在独立函数层面验证，但不能据此宣称整个低码率解码内核逐位一致。最终实现的 8.5k 第一个包能量历史相同，激励历史仍有不超过 `0.0000382` 个原始 PCM 单位的差异；6.5k 首包能量历史部分 float 相差约 `2.38e-7`。后续递归合成会累计这些微小差异。尚未证明某一个后续浮点操作是所有最后 1 LSB 残差的唯一来源，因此没有改写整个闭源 DSP 内核来追求当前样本的绝对逐位相同。

私有试验还恢复了原高通的直接型 float 历史和 x87 加法顺序，以及部分增益预测的 float 存储点。它们没有改善整体误差，部分结果略差，本轮没有合入，也没有为特定样本做补偿。16k 的 345 个 1 LSB 差异仍保留。

这里列出的函数测试使用正常帧分支。原 DLL 的丢包隐藏、错误帧预测分支并未通过这些结果获得完整覆盖；损坏容器仍遵循现代 Reader 的错误返回，不静默伪造修复帧。
