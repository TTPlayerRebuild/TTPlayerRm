# DNET 兼容补丁的 E-AC-3 隔离验证

本轮补上此前仅做分支审查的边界：确认 `TTP_RM_LEGACY_DNET` 的历史 AC-3 补噪恢复不会进入 E-AC-3 解码。

## 样本及参考

生成六条 E-AC-3 音频，覆盖单声道、双声道、5.1，32／44.1／48 kHz，32～448 kbps。按 RM/DNET 的逐字节交换约定封装，每个完整音频帧 1,536 样本，持续约六秒。使用独立 ffprobe 核对采样率、声道和包数。

这是明确构造的 RM 测试载体，**不是从真实历史编码器采集的 E-AC-3 RM 文件**，不借此宣称原版编码器支持产生这种文件。压缩音频由本机 FFmpeg 9.0.1 编码；解码参考则由项目锁定的 FFmpeg 9.0.2 构建，二者职责分开。

同一份 9.0.2 源码分别编译两个私有解码探针：只切换 `TTP_RM_LEGACY_DNET`，同时重新编译 `ac3dec_float.c` 和 `eac3dec.c`，避免上下文结构不同却混用对象文件。探针通过实际 RM 解复用进入解码器，并确认 `AC3DecodeContext.eac3=1`。

## 已确认结果

六条音频在兼容宏开启／关闭时，完整交错 float32 PCM **逐字节相同**。把宏关闭的独立参考量化为 PCM16，实际 RM Reader 输出也逐字节相同、帧数相等、正常 EOF。此前的 AC-3 噪声补丁没有改变这些 E-AC-3 文件的解码结果。

每条音频另按实际 Reader ABI 验证九个定位请求、128 次极小缓冲读取；双声道和 5.1 各增加停止／取消恢复测试。定位后的 PCM 必须与顺序解码逐字节相同。平铺入口共 14 组，最终 `2026.10.29p1` DLL 在 Windows 11、XP SP3、Win7 SP1 全部通过，三份日志均为 `EAC3_CASES=14 FAILURES=0`。

## 范围

- 未增加生产补丁或新解码器，已有 E-AC-3 分支保持原样。
- 不将构造 RM 的验证扩大为真实历史容器、所有 E-AC-3 dependent substream／Atmos 或所有输出设备的验收。
- 原版解码器不是本测试的 E-AC-3 参考；测试针对重建 RM 的后端隔离及 Reader 接口。
- 探针、生成器、样本、PCM、结果和 `stage/run.cmd` 仅位于私有 `rebuild/tests/plugins_followup_20261029p1/eac3`，不进入 Actions 或运行 ZIP。
