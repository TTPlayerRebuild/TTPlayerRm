# ATRAC3／Cook／SIPR 剩余差异补全（2026.11.06p1）

本次继续补齐三个原 RealCodec 库与重建 `ttp_rm` 的差异。播放、编码和新增分包接口全部使用独立源码与静态链接核心，不加载 `atrc.dll`、`cook.dll`、`sipr.dll`。原库仅作为本地私有对照工具。

本文更新 [2026.11.05p1 报告](RM_NATIVE_ENCODERS_20261105P1.md) 中的预设、Cook 尾部、SIPR 丢包处理、RaTC 和定位结论。原报告中的测试数字仍是当时版本的记录，不能替代本次验收。

原版依据包括同一版本二进制的伪代码、初始化状态读取及实际导出调用：ATRAC3 的 `60A03500` 带宽初始化、`60A07CD0` 分配与 `60A079E0` 音调分析；SIPR 的 `614A26E0 / 614A3A90 / 614A30A0` 位图调度和 `614A3340` 的 5k 延迟处理。原 TTPlayer Reader 的 `60601DAB` 给 `RADecode` 传全有效位图，本地文件与网络丢包 API 因此分别验证。地址属于私有对照版本，不能当作任意其他版本的固定入口。

## 1. ATRAC3 预设和带宽

原 `atrc.dll` 的 13 个预设并非 13 套独立算法。逐预设动态对照证明，8–12 五个 Surround 预设分别是 3–7 的参数及编码别名：55 组相同输入的原库输出逐字节相同。因此恢复这些名称和原 flavor 编号是有依据的兼容实现。

重建配置现在提供全部 13 项。原有 INI `Bitrate` 继续有效；增加 `Flavor` 保存别名，仅在其与实际码率匹配时采用。无效、过期或与码率冲突的值回退到基础预设。保存 ATRAC3 设置时一次更新完整节，保留其他键，避免码率和 flavor 分两次保存而出现部分成功。内部别名标记不会写入音频码率。

恢复原编码器的分通道带宽，并同时限制普通频带分配和音调提取。不是只改变界面名称或全局频带上限。

| 目标码率（kbps，约值） | 主／第一编码通道 | 辅／第二编码通道 |
|---|---:|---:|
| 66 | 12,400 Hz | 3,100 Hz |
| 94 | 15,100 Hz | 7,500 Hz |
| 105 | 13,700 Hz | 13,700 Hz |
| 132／146 | 16,500 Hz | 16,500 Hz |
| 176 | 19,200 Hz | 19,200 Hz |
| 265／353 | 22,000 Hz | 22,000 Hz |

离散频带边界按原 `floor(Hz × 2048 / 44100)` 与频带上界转换。最高两个码率未受到本次带宽限制的影响，既有编码位流保持不变。独立心理声学和码字搜索仍不承诺与原闭源编码器逐位相同。

## 2. Cook 输入滤波和输出时序

原 Cook 各预设在攻击检测／MDCT 前调用同一组三个二阶 IIR。按频带数和帧长选择 23 行参数，范围外旁路。新实现保持原浮点状态写回、双精度乘加顺序；100 组滤波检查覆盖全部系数行、旁路和不同输入，每个输出浮点位模式与原实现相同，分块方式不改变结果。

进一步对照原 13 个联合立体声预设的 flavor 路径与通用七参数入口，共 104 组、3,328 个编码包逐字节相同。没有发现 27–29 的 Surround 名称背后还有未接入的独立环绕处理器。既有“分离优先”名称继续描述其联合编码参数，不把名称当作额外 DSP 的证据。

原 Cook 解码接口延后一块发布 PCM。原插件在正常文件 EOF 不调用能排出余留块的 `RAFlush`。重建 Reader 现在暂存当前合成块，下一块成功解码后才发布上一块；正常 EOF 丢弃尚未发布块。重新打开、定位和检查点恢复均维护该状态。

编码端原有的三个收尾包继续保留，保证旧 Reader 能输出真实输入的尾音；不能用删除压缩包代替恢复输出时序。真正的短包、损坏数据仍返回错误，不模仿旧库越界或宽松吞错行为。原先“重建 Reader 多一个合成尾块”的差异由此关闭。

## 3. SIPR 四模式分包与丢包隐藏

增加独立的 5／6.5／8.5／16 kbps 分包解码器。有效位图按最低位优先、每个核心帧一位读取；5k 和 6.5k 每个标准包包含两个核心帧。恢复丢帧插值、衰减、随机数及状态推进；原库每段连续丢失最多输出五个补偿帧的行为也予以保留。

5k 支持两种时序：默认补偿模式直接发布当前帧；显式 Legacy5k 模式保留 240 个采样的启动延迟、参数暂存及跨调用前瞻。Reset 清除待处理帧；要排出 Legacy5k 最后一个参数帧，需要继续提供一个编码帧，空调用不是 flush。

本轮还恢复了有序标量合成、原微小偏置、持续双精度 AGC 累加与五次 Newton 迭代，以及真实的 5k 内部启动帧状态。197 组原库位图／部分帧对照输出长度全部相同，既定样本的最大数值差异为 1 PCM16 LSB。少量数值仍非位精确；没有以统一舍入抹掉差异。四种独立编码器的既有输出 SHA 保持不变。

16k 原库长时间连续丢包时可把音高索引递增到历史缓冲区之前。新版在越界前返回错误并要求 Reset，不复制该越界读取。

### 可选宿主接口

声明位于 `include/ttp_rm_abi.h`。调用 `ttpGetSoundAddIn` 后，在 AddIn 上查询 `iid_sipr_packet_factory`，再调用 `Create(bitrate, flags, out)`；flags 位 0 选择 Legacy5k，其余位拒绝。这是新增可选接口，**不是三个原 DLL 的 RA 导出替身**。

`SiprPacketDecoder` 提供：

- `Format`：调用方先填写 `SiprPacketFormat::size`；返回采样率、包长、包采样数、核心帧采样数和延迟。输出固定为单声道 PCM16。
- `Decode`：调用方提供有效位图及 Buffer，一次最多 32 个核心帧。不完整的最后核心帧位不跨调用保存。输出空间应至少为 `完整核心帧数 × core_samples × 2` 字节。
- `Reset`：丢弃预测历史、待处理帧和失败状态，恢复初始解码状态。

容量不足、空指针等前置校验不推进解码状态；调用方可调整 Buffer 后重试。合成失败或最终 `SetLength` 发布失败后，后续 Decode 返回失败直到 Reset。不能拿部分输出当作成功 PCM。空输入返回零长度，不排出延迟帧。

原导出 ordinal 1、Reader 的枚举 0、三个 Encoder 的枚举 1–3 及原有接口槽位不变。普通本地 RM 文件没有有效位图，仍走原 Reader 路径，不把物理截断自动转换成可隐藏的网络丢包。

## 4. 原始 RA4 边界和 RaTC

`RaTC` 是 `(FourCC, 文件绝对偏移)` 的块目录，不是时间／采样索引。RA4 的 `.ra4` 块长包含头部和对齐填充，另一个字段才是压缩音频字节数。新版分别处理这两个值，不再将目录或保存后的标签当成音频，也不以容器尾长计算时长。

对已知长度的 RA4：

- 按声明音频范围读取，允许 0–3 字节块对齐；真实短读、未完成交织组返回错误。
- 校验可选 RaTC 的大小、项对齐、偏移、目标 FourCC、音频和自身条目；损坏的可选目录不改变声明音频范围。
- 目录读取／定位的普通失败可忽略，但必须强制恢复底层流的音频位置，不能只恢复 AVIO 缓冲指针。恢复音频位置失败或用户取消仍向宿主报错。
- 标签保存继续保留完整容器及目录，不截断 RaTC。未知长度和非适用旧头保留原兼容读取路径，不能宣称所有旧 `.ra` 截断情况均已覆盖。

## 5. 精确定位缓存

继续保证定位结果等于当前 DLL 线性解码的对应 PCM；不通过直接跳到 INDX 项而丢失预测、重叠和补噪状态。

为 Cook、ATRAC3、SIPR 增加内存检查点，保存有类型的数值状态、RM 交织缓冲、逻辑位置和 Cook 待发布块。指针、FFmpeg 对象和 AVPacket 本体不作裸内存复制；恢复前核对完整配置、extradata、形状和边界。SIPR 高通缓冲的指针方向使用索引恢复。

每约五秒在完整输出边界尝试记录，检查点上限 8 MiB／256 项，另保留既有 4 MiB PCM 历史缓存。它们属于单个 Reader，不写磁盘。只能在通用容器包队列为空且交织矩阵完整可验证时保存。Int0 多帧包及不适合快照的路径安全回退到线性重放。

定位优先使用 PCM 历史，其次从目标之前最近的有效检查点恢复并精确丢弃。可选快照创建失败不影响播放；实际 I/O 错误和取消继续执行已有恢复逻辑。10 个长文件覆盖长交织、单包交织、Cook 多声道、SIPR 四模式及 Int0：240 次随机定位、30 次完整后缀和 40 次取消回滚均逐字节一致。九个可缓存文件的既定测试位置底层读取减少 50%–77.8%；这不是对所有音频文件的统一速度保证。

## 6. XP 动态加载及退出修复

最终虚拟机验收发现构建层面的真实遗漏：手工链接 YY-Thunks 对象文件的 DLL 需要使用它的专用入口，而原项目仅链接了对象、仍使用普通 CRT 入口。XP 动态加载带 TLS 的模块时需要该入口分配／维护 TLS 索引；遗漏后可能与同样使用 YY-Thunks 的宿主 TLS 索引混用，表现为测试内容通过、进程退出访问异常。

最小探针证明不调用导出、不编解码，仅加载 DLL 就能复现；移除探针的 YY 对象或换成部分其他客户端又不复现。因此没有用更换测试程序或强制结束进程来掩盖问题。

按固定 YY-Thunks 1.2.2 随包 Readme 的手工 DLL 接入要求，正式 x86 DLL 增加：

```text
/ENTRY:DllMainCRTStartupForYY_Thunks
/alternatename:_YY_ThunksOriginalDllMainCRTStartup@12=__DllMainCRTStartup@12
```

专用入口先处理 XP TLS，再转交原 CRT／DllMain，并负责相应线程和卸载清理。仅重新链接、算法对象不变的对照候选使原失败探针和未修改宿主的新增 23 项测试正常退出；正式候选随后通过了完整三系统回归。此项是生产 DLL 的集成修复，不能归类为测试辅助程序错误。

## 8. 尚不能宣称完全一致的部分

- ATRAC3／Cook／SIPR 独立编码器的心理声学、搜索选择和全部瞬态决策不保证与原库逐位一致；合法兼容码流不等于相同编码器或感知音质相同。
- 部分原库 PCM 对照仍有最多 1 LSB 的残差；该结论只覆盖实测样本。
- 没有提供可直接替换三个 RealCodec DLL 的全部低层 RA 导出。新增分包功能通过 ttp_rm 可选 QI 接口暴露；原宿主文件播放和转换不需要三个原 DLL。
- 特殊 ATRAC3AL 和真实多码率 SureStream 尚缺完整动态样本验收。原插件伪代码显示选择音频 MDPR 和物理流号，尚不能据此证明原版实现了完整自适应码率。新版底层已有 MLTI 解析，不应把“未验证”写成“确定未实现”。
- 未发现原三个库／插件链路完成受保护内容播放的充分证据。CONT 版权文字、密码入口或握手不能当作 DRM 播放证据；未把 DRM 写成必须补齐的已证实原功能。

本轮关闭的是已有静态／动态证据能够明确界定的功能差异和错误边界，保留上述可核查的限制。
